# Как разобраться в коде перед защитой

Сначала разбери три новых алгоритма по отдельности. Начни с общей функции обхода: она используется во всех трёх. Формат JSON уже обеспечивает шаблон.

## Знакомые конструкции

| Код | Что означает |
|---|---|
| `vector<int> a(n, -1)` | Массив длины n, все значения -1 |
| `vector<vector<int>> graph(n)` | У каждой вершины свой список соседей |
| `push_back(x)` | Добавить в конец |
| `back()` | Посмотреть последний элемент |
| `pop_back()` | Удалить последний элемент |
| `reverse(a.begin(), a.end())` | Развернуть массив |
| `continue` | Перейти к следующей итерации цикла |
| `return` | Закончить функцию и вернуть результат |
| `J::A` | Массив для JSON-ответа |
| `J()` | JSON-значение null |
| `const vector<...>&` | Читать существующий массив, не копируя и не изменяя его |

## Общая функция dfsFinishOrder

DFS заходит как можно глубже, затем возвращается назад. Здесь возвращение организовано массивом `path`, который работает как стек: последним пришёл — первым ушёл.

Вместо вызовов функции самой себя используем `while`. Это нужно, потому что по заданию может быть цепочка из 100000 вершин, а рекурсия способна переполнить стек вызовов.

Переменные:

| Переменная | Значение |
|---|---|
| `color[v] == 0` | В вершину v ещё не заходили |
| `color[v] == 1` | Вершина v сейчас в пути обхода |
| `color[v] == 2` | Вершину v полностью закончили |
| `nextEdge[v]` | Индекс следующего соседа, которого надо проверить |
| `path` | Текущий путь обхода |
| `order` | Вершины в порядке завершения |
| `acyclic` | Осталось true, если не нашли цикл |

Сначала берём последнюю вершину пути:

```cpp
int vertex = path.back();
```

Если всех её соседей уже посмотрели:

```cpp
if (nextEdge[vertex] == graph[vertex].size())
```

то ставим цвет 2, добавляем вершину в `order` и убираем из `path`. Так возвращаемся к предыдущей вершине.

Иначе берём следующего соседа:

```cpp
int next = graph[vertex][nextEdge[vertex]];
nextEdge[vertex]++;
```

Если сосед имеет цвет 1, он уже в текущем пути. Ребро вернулось к предку — нашли цикл. Если цвет 0, отмечаем 1 и добавляем в путь. Цвет 2 означает, что сосед уже обработан; повторно заходить не нужно.

Пример `0 -> 1 -> 2`: путь растёт `[0]`, `[0,1]`, `[0,1,2]`. Затем вершины заканчиваются в порядке `[2,1,0]`. Для топологического порядка разворачиваем: `[0,1,2]`.

`nextEdge` нужен, чтобы после возврата продолжить с нужного соседа, а не смотреть всех сначала. Каждый сосед проверяется один раз.

## SCC — группы взаимно достижимых вершин

Например, для `0 -> 1`, `1 -> 0`, `1 -> 2` вершины 0 и 1 входят в одну группу, а 2 — в другую.

Код делает следующее:

1. Заполняет `graph`: для ребра a -> b записывает b в список a.
2. Заполняет `reversed`: записывает обратное ребро b -> a.
3. Получает порядок завершения первого DFS и разворачивает его.
4. В этом порядке начинает обходы обратного графа. Все найденные за один обход вершины получают одну метку `label`.
5. Строит рёбра между группами.

`component[v] == -1` означает, что вершина ещё не получила группу. Метка ставится сразу при добавлении в стек, чтобы не добавить одну вершину несколько раз.

В примере результат может быть `component = [0,0,1]`, `condensation = [[0,1]]`. Номера групп могут отличаться, важен состав.

`seen` — множество уже добавленных связей между группами. Строка `1LL * from * n + to` упаковывает пару меток в одно число. Например, при n=5 пара (2,3) превращается в 13. Метки меньше n, поэтому разные пары дают разные числа. `1LL` включает 64-битное вычисление.

Почему два обхода? Первый даёт порядок, в котором на обратном графе можно выделять по одной целой группе, не захватывая следующую. Произвольный порядок такого свойства не имеет.

## topo — топологическая сортировка

`topo` строит списки соседей и вызывает общий DFS.

- Если `acyclic == false`, возвращает пустой `order`.
- Иначе разворачивает список завершения и возвращает его.

Для ребра a -> b вершина b заканчивается раньше a. После разворота a будет перед b — именно это нужно топологической сортировке.

Три цвета отличаются от одного `visited`: надо отличать вершину, которая ещё в текущем пути, от вершины, которую закончили раньше. Только возврат к первой доказывает цикл.

## dag — кратчайшие пути

Сначала проверяется весь граф на циклы. Даже если цикл недостижим от source, задание требует вернуть false.

Дальше код хранит:

| Массив | Что хранится |
|---|---|
| `distance[v]` | Лучшая найденная стоимость до v |
| `reachable[v]` | Найден ли вообще путь до v |
| `parentEdge[v]` | Номер последнего ребра лучшего пути до v |
| `outgoing[v]` | Номера исходящих рёбер v |

Только source изначально достижим; его стоимость равна нулю. Остальные нули в `distance` пока ничего не означают, потому что для этих вершин `reachable == false`.

В топологическом порядке берём вершину и проверяем каждое исходящее ребро:

```cpp
long long candidate = distance[vertex] + weight;
```

Это стоимость пути до соседа через текущую вершину.

```cpp
if (!reachable[next] || candidate < distance[next])
```

Читается: «если сосед пока недостижим ИЛИ новый путь дешевле». Тогда записываем новую стоимость и номер ребра.

Например, до A стоимость 3, ребро A -> B весит -7. Новый путь до B стоит -4. Если раньше было 8, заменяем 8 на -4.

Отрицательные веса здесь допустимы: циклов нет, а все возможные предшественники обработаны раньше вершины. Это алгоритм для DAG, не Дейкстра.

## reconstructRoute — восстановление маршрута

До вершины 3 пришли по ребру №7, которое ведёт 2 -> 3. Значит, предыдущая вершина — 2. Смотрим её входящее ребро, затем предыдущее, пока не дойдём до source.

```cpp
int id = parentEdge[vertex];
vertex = edges[id][0];
```

Ребро хранит `[откуда, куда, вес]`, поэтому `[0]` даёт предыдущую вершину. Собрали маршрут от конца к началу — разворачиваем. Если встретили -1 до source, пути нет. Если цель равна source, результат `[source]`.

## Короткие ответы для защиты

| Вопрос | Ответ |
|---|---|
| Что делает DSU? | Хранит разбиение на множества и быстро их объединяет. |
| Что хранит parent? | В DSU — родителя в дереве. В DAG parentEdge — исходный ID входящего ребра. |
| Почему Kruskal вызывает unit? | Ребро берётся, только если соединяет разные компоненты и не создаёт цикл. |
| Почему Prim использует очередь? | Чтобы быстро извлекать самое дешёвое ребро от уже взятых вершин. |
| Что такое SCC? | Максимальная группа вершин, из каждой можно дойти в любую другую. |
| Зачем в DFS три цвета? | Отличать активный путь от уже завершённых вершин и находить циклы. |
| Зачем разворачивать finish order? | Зависимость u -> v должна поставить u раньше v. |
| Почему цикл ищем во всём DAG? | Таково условие задания, включая недостижимые компоненты. |
| Зачем long long? | Сумма весов может превысить диапазон int. |
| Почему всё не рекурсивно? | Чтобы обрабатывать глубину 100000 без переполнения стека вызовов. |

Порядок самостоятельного разбора: проследи DFS на цепочке 0 -> 1 -> 2, затем добавь 2 -> 0 и посмотри, где появляется цвет 1. После этого разбери topo, SCC и DAG по очереди.
